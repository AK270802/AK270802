Layer 04 / Weights

The stack, with the reasons attached.

Tools are cheap to list and expensive to choose well. Each group below comes from systems described on the projects and experience pages — not from a tutorial.

Agentic & LLM systems

The core of my current work: multi-agent pipelines where each agent has a narrow contract, a supervisor, and a measurable output. Retrieval grounds generation before it happens.

  • LangGraph
  • Multi-agent orchestration
  • RAG pipelines
  • Prompt & context engineering
  • LLM evaluation & guardrails
  • Docling document parsing

Applied ML

Forecasting and scoring models that run on schedules, not in notebooks — with a feature store so six platform modules share one definition of truth, and MLflow so every model in production can be traced back.

  • XGBoost
  • Prophet
  • MLflow
  • Feast
  • scikit-learn
  • Model monitoring

Data & infrastructure

The unglamorous layer that decides whether AI features work at 3am: orchestration, async processing, and the cloud primitives underneath a multi-tenant platform.

  • Airflow
  • Celery
  • Redis
  • AWS
  • Kubernetes
  • MinIO
  • Docker

Backend

Where the AI meets the product: APIs with authentication, tenancy, rate limits and audit trails. Django for platform surface area, FastAPI for focused microservices like Kestrel.

  • Django / DRF
  • FastAPI
  • Python
  • PostgreSQL
  • REST API design

Frontend

Enough to architect and review the client side of a SaaS honestly — LexAI's frontend is Next.js 14, chosen for server components and route-level data loading, not fashion.

  • Next.js 14
  • React
  • TypeScript

Vector & search

Retrieval quality caps everything downstream of it. Qdrant in production for LexAI, with bge-small embeddings picked deliberately: strong recall at a latency and hosting cost small firms can afford.

  • Qdrant
  • Embedding models (BAAI/bge)
  • Hybrid retrieval
  • Chunking strategies
